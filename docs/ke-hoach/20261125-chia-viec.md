# Chia việc: dựng lại Xưởng in Minh Trí

Dựa trên: `docs/yeu-cau/20261125-dung-lai-xuong-in-minh-tri.md`, `docs/thiet-ke/20261125-dung-lai-xuong-in-minh-tri.md` (đã duyệt), `CONSTRAINTS.md`. `DESIGN.md` sẽ có ở đợt 1.
Trạng thái: **Đề xuất, chờ người quản lý duyệt.**

## Chạy ở đâu
Theo ý người quản lý, code chạy trên máy người quản lý (`D:\agent-project\printing-workshop`, mở trong VS Code) qua Remote Control, Claude Code ở đó có plugin `bo-chuan`. Điều phối giao từng đợt; mỗi thẻ một agent chạy nền, mỗi agent một worktree và nhánh `feat/<ma-the>-<ten>`. Mỗi thẻ xong có một agent khác review theo thẻ rồi mới gộp. Một đợt gộp thành một PR vào `main`.

## Ước lượng
- 30 thẻ, mỗi thẻ khoảng 1 giờ agent. Chạy tối đa 5 song song: **9 đợt**, cộng review và gom mỗi đợt.
- Thời gian thực phụ thuộc giờ máy người quản lý bật và các mốc duyệt. Ước lượng **5–8 ngày làm việc** nếu máy bật cả ngày; làm tuần tự một agent sẽ khoảng 4–5 tuần.
- Phần khó nhất: TIF (W1, khối Photoshop) và file cắt, 8 thẻ.

## Mốc người quản lý xem
1. **Sau đợt 1:** DESIGN.md + màn mẫu + ảnh chụp (duyệt giao diện, quyết định thẩm mỹ).
2. **Sau đợt 4:** ghép được bộ nghiệm thu từ giao diện thật, xem số liệu và bảng chia mét.
3. **Sau đợt 7:** tải PDF, TIF, file cắt; người quản lý mở TIF trong Photoshop, file cắt trong Illustrator theo checklist đặc tả 10.4, 10.5.
4. **Sau đợt 8:** báo cáo review độc lập, rồi gói phát hành.

## Rủi ro và giả định
- Máy người quản lý phải bật, không ngủ trong lúc chạy đợt. Mất kết nối thì đợt dừng, chạy tiếp được.
- CHUAN cần app cũ chạy trên máy người quản lý (Java đã có). Nếu app cũ không chạy được, dùng số trong đặc tả làm chuẩn và chỉ so TIF với `IN6 2209.tif`.
- CI GitHub không có hồ sơ màu (ADR-004): test màu CMYK chạy trên máy người quản lý trước mỗi lần gộp đợt 5–7.
- Mỗi thẻ ≤ 5 file: thẻ TIF và file cắt sát giới hạn, có thể phải tách thêm thẻ khi viết chi tiết.
